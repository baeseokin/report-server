# 테스트 케이스 상세

각 테스트가 **어떤 사용자로 로그인해서, 무엇을 요청하고, 무엇을 확인하는지** 순서대로 적었습니다.
테스트 코드를 바꾸면 이 문서도 함께 고쳐 주세요.

---

## 0. 공통 준비

### 0-1. 테스트 DB 초기화
- 테스트를 시작할 때 한 번: `reportdb_test` DB를 지우고 `db/schema.sql`로 다시 만듭니다. (`tests/globalSetup.js`)
- **각 테스트 직전마다**: 모든 테이블을 비우고 아래 기초 데이터를 다시 넣습니다. (`tests/helpers/fixtures.js`의 `resetDb`)
  그래서 테스트끼리 서로 영향을 주지 않습니다. 단, `auth.test.js`는 파일 시작 때 한 번만 초기화합니다.

### 0-2. 로그인 비밀번호
- 테스트 사용자는 **모두 같은 비밀번호 `pw`** 를 씁니다.
- `resetDb`가 `pw`를 bcrypt로 암호화한 값(빠른 실행을 위해 cost 4)을 모든 사용자의 `password_hash`에 넣습니다.
- 운영 DB의 실제 사용자·비밀번호는 쓰지 않습니다. 테스트 DB는 매번 새로 만드는 별도 DB입니다.
- 로그인은 실제 화면과 같은 `POST /api/login { userId, password: "pw" }`로 하고, 받은 세션 쿠키를 이후 요청에 사용합니다. (`tests/helpers/app.js`의 `loginAs`)

### 0-3. 부서

```
교회(1)
├─ 음악부(2)
│   └─ 원천엔젤스(3)
├─ 재정부(4)
├─ 교육부(5)
│   └─ 청년부(6)
├─ 공백부(7)        ← 결재선 순번에 공백이 있는 부서
└─ 위원장없음부(8)  ← 위원장 결재선이 없는 부서
```
